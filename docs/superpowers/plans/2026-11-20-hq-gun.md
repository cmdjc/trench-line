# Aimable HQ Gun Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every nation an aimable, pay-per-shot HQ gun with its own range, cost, reload and shot pattern, and let the enemy fire one at you.

**Architecture:**
- The gun data lives in a new table, `src/data/guns.js`.
- Gun state (`G.gun[side] = { cd }`) and firing live in a new browser-free module, `src/sim/gun.js`. Firing pushes shells into the existing `G.shells` pipeline with a `noBase` flag, so HQs are never damaged.
- The aim flow reuses `G.aim` with a new `kind` field (`'paris' | 'gun'`), so there is only ever one aim at a time.
- The enemy fires from `aiStep`, using a range-aware cluster scorer.

**Tech Stack:** Vanilla ES modules, canvas, Vite, Vitest, jsdom e2e.

**Spec:** `docs/superpowers/specs/2026-11-20-hq-gun-design.md`

## Global Constraints

- `src/sim/**` and `src/data/**` stay browser-free.
- Determinism: same seed, same battle. No new rng draws before t = 60 s on any path; after that, the enemy gun may draw.
- HQ guns never damage either HQ.
- Only one aim is active at a time. The Paris Gun flow keeps working unchanged for `kind: 'paris'`.
- Charges happen exactly once, and a rejected action never charges.
- Aiming is tap-only, by user decision. The Aim, Confirm and Cancel buttons are real `<button>`s.
- Starting numbers per gun (range in trenches / cost / reload in seconds):

  | Nation | Range | Cost | Reload |
  |---|---|---|---|
  | gb | 3 | 40 | 8 |
  | de | 6 | 30 | 6 |
  | fr | 5 | 60 | 12 |
  | us | 9 | 90 | 20 |
  | ah | 4 | 50 | 10 |
  | aq | 3 | 35 | 10 |
  | it | 3 | 120 | 30 |
  | ru | 5 | 80 | 25 |

- Shot patterns (number of shells): gb 3, de 1, fr 4, us 1, ah 1 (low `cov`), aq 5, it 1 (huge), ru 6 (scattered).
- `npm run check` and `npm run e2e` must pass at the end of every task.

## Review Focus

1. **Tapping beyond range:** the target clamps to the max-range x and is never refused. (Task 2 test `clamps`.)
2. **Starting a gun aim while a Paris aim is active, or the reverse:** the old aim is replaced, and nothing is charged. (Task 2 test `one aim`.)
3. **Confirming while reloading or short of supplies:** returns false and charges nothing. (Task 2 test `rejects`.)
4. **Shells landing on or near an HQ:** HQ hp is unchanged. (Task 2 test `noBase`.)
5. **Maps with more trenches than the range, and maps with fewer:** range is capped at trench `G.NT`, and the AI side is mirrored. (Task 2 test `range`.)

### Task 1: Gun data

**Files:**
- Create: `src/data/guns.js`
- Test: `tests/unit/data.test.js`

**Interfaces:**
- Produces: `GUNS[nation] → { name, range, cost, cd, shells: [{ dmg, splash, cov, spread, delay, dur, arc, big? }] }`
  - One entry per shell, fired in order. `delay` (seconds) staggers the shells. `spread` is the random scatter radius in px.
  - Names: gb 'Stokes mortar battery', de '7.7 cm FK 16', fr '75 mm battery', us '155 mm GPF', ah 'Mountain gun battery', aq 'Penguin mortar', it '210 mm mortar', ru 'Massed battery'.
  - Per-shell damage, splash and spread are the implementer's call, scaled against the existing shells (Paris 700/90, 42 cm 180/70, Kettering bug 110/42). The rules:
    - It's 1 shell is the biggest (≈ 260 dmg / 80 splash).
    - Small shells are 40–70 dmg / 25–35 splash.
    - ah `cov` is ≥ 0.9; the others are 0.7–0.85.
    - ru `spread` ≥ 60.

### Task 2: Gun sim and player commands

**Files:**
- Create: `src/sim/gun.js`
- Modify: `src/sim/state.js` (`G.gun = [{cd:0},{cd:0}]` in `newGame`), `src/sim/tick.js` (call `stepGun(dt)`), `src/sim/combat.js` (shells with `noBase` skip HQ damage), `src/sim/commands.js`
- Test: `tests/unit/gun.test.js` (new), `tests/unit/commands.test.js`

**Interfaces:**
- Produces:
  - `gunMaxX(side) → number`: the furthest reachable x. For side 0 it is `G.LX[min(range, G.NT)] + halfGap`, and side 1 is mirrored. `halfGap` is half the distance to the next line.
  - `clampAim(side, x) → number`
  - `gunBlock(side) → string`: `''` when ready, otherwise a plain sentence, e.g. "Reloading: ready in N seconds."
  - `fireGun(side, x, y) → boolean`: pushes the shells with `noBase: true` and the gun's type, sets `G.gun[side].cd = cd`, and **does not charge**. Scatter uses `rng`.
  - `stepGun(dt)`: counts both cooldowns down.
  - `commands.startGunAim()`: sets `G.aim = { kind: 'gun', x: null, y: null }`, replacing any aim.
  - `commands.startAiming()` (Paris) now sets `kind: 'paris'`.
  - `commands.confirmAim()` branches on `G.aim.kind`. For `'gun'` it checks `gunBlock(0) === ''` and supplies ≥ `GUNS[n].cost`, clamps x, fires, charges once, clears the aim, and toasts "<gun name> fired." For `'paris'` it behaves as today.
- [ ] **Step 1: Failing tests** in `gun.test.js`:
  - `range`: on 'open', `gunMaxX(0)` for gb is `G.LX[3] + 115`. us (9) caps at `G.NT`. Side 1 mirrors.
  - `clamps`: confirming at x = `G.WW` lands every shell's `x1` at ≤ `gunMaxX(0) + spread`.
  - `fires and charges once`: supplies drop by the cost, the shell count matches `GUNS`, and cd is set.
  - `rejects`: while reloading, or with supplies < cost, it returns false and nothing changes.
  - `one aim`: `startGunAim` replaces a Paris aim (`kind` becomes 'gun'), and the reverse also holds.
  - `noBase`: a de gun shell fired at `G.bases[1].x` doesn't change `bases[1].hp` after the shells resolve. Step `tick` until the shells are gone.
  - `no rng before use`: with no gun fired, rng output after 30 s of `tick` matches a run on the commit before this task. Simplest check: the existing smoke and parity tests stay green unchanged.
  - Also update the Paris tests in `commands.test.js` that assert `G.aim` equals `{x:null,y:null}` so they include `kind: 'paris'`.

### Task 3: Enemy fires its gun

**Files:**
- Modify: `src/sim/gun.js` (add `bestTarget`), `src/sim/ai.js`
- Test: `tests/unit/ai.test.js`

**Interfaces:**
- Produces: `bestTarget(side) → { x, y, value } | null`. It uses the same 85 px cost-weighted cluster score as `aimPoint` in src/sim/superweapons.js, restricted to foe units with `x` within the side's range, `hp > 0` and `!fixed`.
- In `aiStep`'s buy block, add a check after all existing rng draws on that tick. When `G.S.t >= 60`, `gunBlock(1) === ''` and `ai.money >= cost * 3`, and `bestTarget(1)` is non-null with `value >= cost`:
  - Fire with probability 0.25 per buy tick (`rng.float()`).
  - Pay `cost` from `ai.money`.
  - Call `fireGun(1, t.x, t.y)`.
  - Show no toast.
