# Trench Line: handoff

A top-down First World War trench battle game: one HTML file, vanilla JS, a single `<canvas>`, no build step and no runtime dependencies. This document is the code map for whoever turns it into a proper JS/HTML project. What the game contains and why is in `DESIGN.md`; every number is in `STATS.md`.

## Files

| Path | What it is |
|---|---|

## Code map

Everything is inside one IIFE in a single `<script>`. Sections are marked `/* ---------- name ---------- */`, in this order:

| Section | Key contents |
|---|---|
| constants | `UT` (base unit stats), `NU` (per-country overrides), `INF`, `TK`, `ORDER`, `DBL`/`isDbl`, `HEDGE` |
| tank variants | `TKB`, `tkv()`, one `Object.assign(NU.xx,{...})` per country, `STATS`, `tkList`, `tkPrev`, `SPECIAL`, `ut(side,k)`, `COV`, `ARM`, `NESTCOV`, `NAT`, `AI_*` |
| permanent research | `TECH`, `META`, `loadMeta`/`saveMeta`, `makeCode`/`readCode`, `applyTech` |
| state | `SW`, `MAPS`, `setLayout(key)`, `mods()`, `newGame(mine,theirs,map)` |
| geometry | `posX`, `trenchX`, `startX`, `spawn`, `count`, `tanks`, `full`, `countAt`, `power`, `frontLine` |
| combat | `hurt`, `accVs`, `die`, `stepUnits` (movement, bridges, hedgehogs, firing, shells, ownership, garrison, super trench) |
| fortifying and MG nests | `freeSlot`, `wireSlow`, `stepFields`, `buildDef`, `buildNest`, `stepJobs`, `fortify`, bunkers |
| superweapons | `targetFor`, `swBlock`, `useSW`, `detonate`, `stepSW`, Paris Gun aiming |
| enemy commander | `aiStep`, `aiThink` |
| cards | `CARDS`, `CARDTXT`, `relabelCards`, `offerCards` |
| orders, interface | `select`, `buildMap`, `buildBuy`, `refresh`, research and save-code UI, `renderStart`, `endGame` |

| drawing | `draw`, `drawTankGen` (parts-list renderer), one `draw*` per hand-drawn unit and structure |
| camera input, loop | drag scrolling, `frame` |

## Conventions

- **Sides:** `0` is the player (left), `1` the enemy (right). `nation[side]` is the country code.
- **Lines:** `0` is the player's HQ, `1..NT` are trenches, `HQI` (= `NT+1`) is the enemy HQ. `LX[L]` is the x of line `L`. `setLayout` rebuilds `LX`, `NT`, `HQI`, `WW` per map; never hard-code 9 or 10.
- **Special trenches:** `SUPER` is one line index (the Long March's neutral super trench, or `-1`). `DBL` is a list of double trenches (Wide open plain). They have different rules; see `DESIGN.md`.
- **Unit:** `{side,type,T,line,x,y,ly,hp,max,cd,settled,moving,fixed,park,...}`. `T` is the resolved stat object; read stats from `u.T`. `fixed` marks units that ignore orders (emplacements, sappers). `ly` is the home lane; `y` wanders only to cross bridges.
- **Armour:** `T.armor` marks vehicles. `T.w` is how much of the nation's armour limit one uses. `T.sup` marks superweapon vehicles, which do not count. `T.big` marks giants that ford rivers and roll over hedgehogs. `T.draw` is a parts list for `drawTankGen`; without it `drawTank` falls back to a hand-drawn function chosen by country.
- **Attack type:** damage tables are keyed by `T.atk || u.type`. Anything that is not one of the six base types must set `atk`, or lookups return `undefined` and damage becomes `NaN`.
- **Modifiers:** `M[side]` from `mods()` holds multipliers changed by traits, cards and research. Any new unit type key must be added to the list in `mods()`.
- **World size:** 300 units high; `K` scales it to the canvas. `cam` is the left edge in world units.
- **Test hook:** `window.__trench` exposes `units() fort() fields() jobs() sw() step(sec) draw() info()`; `tests/harness.js` injects more. Keep it, or an equivalent, behind a debug flag.
- **Storage:** the source uses `window.storage` (an async key-value API in the chat preview). The Artifact copy falls back to `localStorage`. Pick one adapter.
- **Saves:** research only. Two slots (`trenchline-meta`, `trenchline-meta-b`), newest valid wins. Save code `TL1-<points>-<techMask>-<runs>-<wins>-<check>` in base 36; `techMask` follows `TECH` declaration order, so append nodes only or bump the prefix.

## Suggested path to a proper project

1. Lift `<style>` and `<script>` into `styles.css` and ES modules, one per section above.
2. Put the mutable state (`units`, `S`, `M`, `owner`, `fort`, `fields`, `jobs`) in one module so the simulation runs without a DOM.
3. Separate simulation from UI: `toast()` and `refresh()` are called from simulation code; route them through events.
4. Move data (`UT`, `NU`, `NAT`, `SW`, `CARDS`, `TECH`, `MAPS`) into plain data files.
5. Replace `Math.random()` in the simulation with a seeded generator. Runs are not repeatable today, which makes balance testing noisy.
6. Call the headless simulation directly from tests in place of jsdom.

## Not verified

- Nothing has been played by hand. Touch scrolling, double-tap to fortify, Paris Gun aiming and the scrolling trench strip are untested on a phone.
- Balance: scripted results swing widely between runs. See "Known quirks" in `DESIGN.md`.
- The save-code and two-slot recovery tests from an earlier session were lost and have not been rewritten. The merge did not touch that code.

## How the owner likes to work

They ask to be asked two or three short multiple-choice questions before each new feature, and answer quickly. They care about historical flavour: named units, real superweapons, distinct art per country.
